🔑 Where to get Google OAuth credentials

1. Go to Google Cloud Console
   👉 [https://console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials)

   (Make sure you’re logged in with the same Google account you use for your project.)


2. Select your project

   * Top bar → Project dropdown.
   * Use the same project where you enabled “Google+ APIs / Identity” (now called *Google Identity Services*).


3. Create OAuth Client ID (if not already done)

   * Left sidebar → Credentials
   * Click + Create Credentials → OAuth client ID
   * Application type = Web application
   * Name = something like `Supabase OAuth Web`
   * Authorized JavaScript origins:

     
     http://localhost:3000
     https://vcbcrvkcfolvskrnxuyd.supabase.co
     
   Authorized redirect URIs:

     
     https://vcbcrvkcfolvskrnxuyd.supabase.co/auth/v1/callback
     
   Save.


4. Copy your Client ID and Secret

   * In the list of OAuth 2.0 Client IDs, click your new credential.
   * You’ll see:

     * Client ID: `1234567890-abcdefghijklm.apps.googleusercontent.com`
     * Client secret: long random string like `GOCSPX-qlAQsw...`



🔧 Paste into Supabase

Now in Supabase Dashboard → Authentication → Providers → Google:

* Client IDs → paste the Client ID string (or multiple IDs, comma separated).

  
  1234567890-abcdefghijklm.apps.googleusercontent.com
  

* Client Secret → paste the secret string.

* Callback URL (should already be filled):

  
  https://vcbcrvkcfolvskrnxuyd.supabase.co/auth/v1/callback
  

* Skip nonce checks → ❌ Leave unchecked for web apps.

* Click Save.

* Now your “Sign in with Google” button should work.

If you still see `redirect_uri_mismatch`, it’s usually one of these:

* The Client ID in Supabase doesn’t match the one you configured in Google (double-check character-for-character).
* You pasted the wrong secret or didn’t hit Save in Supabase.
* You edited a different OAuth client in Google than the one whose Client ID you put in Supabase.

If that happens, copy the exact `redirect_uri=` string from the Google error page and compare it (byte-for-byte) with the entry under Authorized redirect URIs in Google. They must be identical.
